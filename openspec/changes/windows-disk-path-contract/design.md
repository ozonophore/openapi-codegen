## Context

`pathHelpers` (`joinHelper`, `resolveHelper`, `relativeHelper`, `normalizeHelper`, `dirNameHelper`) уже заменяют `\` на `/`. Сравниваемые и сохраняемые строки дисковых путей, тесты и несколько мест в production-коде по-прежнему используют нативные `path.join` / `path.sep`. На Windows эта смесь ломает равенство, `startsWith`, проверки листинга, Git `show` и сравнение снимков.

`OutputGroupResolver` считает LCA по `/`, затем конвертирует обратно в `path.sep`. Тесты записи передают `outputPath: '/'` (корень диска на Windows). `rmSync` временного каталога бросает `EBUSY`. `readSpecFromGit` подаёт `path.normalize` в `git show`, получая `test\\spec\\v3.json`.

Это изменение — контракт строк дисковых путей для CLI и записи `.ts`. Это не Tree `$ref` / `$ref` lookup (`pathHelpers` остаются для диска; RefLookup — другое изменение).

## Goals / Non-Goals

**Goals:**

- После `pathHelpers` сравниваемые/сохраняемые строки дисковых путей используют `/`. Тесты проверяют через `joinHelper`, не через нативный `path.join`.
- LCA в `OutputGroupResolver` MUST NOT конвертироваться обратно в `path.sep` (`\`).
- Исправить расхождения строк дисковых путей в EntitySkip, ProjectProbe, analyzeUsage (Client / Import / Service / rename), `isSubDirectory` и в проверках листинга generation cache.
- Общий тестовый хелпер для Windows `rmSync` временных каталогов: повторная попытка, затем игнорировать `EBUSY`. Это не изменение production-генератора.
- Production MUST отказывать в mkdir/write корня диска (`/`, `D:\`, `C:\`). Тесты успешной записи используют настоящий временный каталог. Отдельные тесты ожидают понятную ошибку для `/` и `D:\`.
- Пути Git CLI MUST быть POSIX (`test/spec/v3.json`), не `test\\spec\\v3.json`.
- `toMatchSnapshot` нормализует и expected, и received к `\n` перед сравнением.

**Non-Goals:**

- RefLookup, отсутствующая модель Nested.ts, expandOpenApiRefs, снимки semantic-diff, PathApi (уже удалён).
- Смена EOL файлов генератора.
- Правки `CONTEXT.md` или добавление терминов глоссария.
- Трактовка строк дисковых путей как Tree `$ref` / `$ref` lookup.

## Decisions

1. **Слеш после `pathHelpers` — форма строки дискового пути.** Места вызова, которые сравнивают или сохраняют пути, MUST использовать результат хелпера как есть (`/`). Тесты MUST проверять через `joinHelper` (или тот же хелпер, который породил значение), не через `path.join`. Альтернатива: оставить нативные разделители на границе ФС — отвергнута; Node принимает `/` на Windows, а смешанные формы и есть баг.

2. **`OutputGroupResolver` сохраняет LCA со `/`.** Убрать финальный `lca.replace(/\//g, sep)`. Детекция тривиального корня остаётся на форме со слешем (`/`). Альтернатива: конвертировать в `path.sep` «для файловой системы Windows» — отвергнута; это снова вносит `\` в конвейер, который уже нормализован к `/`.

3. **То же изменение чинит перечисленные места расхождений.** EntitySkip: кэшированные `files` / тестовые пути; ProjectProbe: префикс `srcRoot` (`path.sep` vs `/` от хелпера); analyzeUsage: Client / Import / Service / rename и `apiImportScope`; `isSubDirectory`; проверки листинга generation cache через `readdir`. Без новой абстракции путей сверх существующих `pathHelpers`.

4. **`EBUSY` — только тестовый хелпер.** Общий хелпер вокруг `rmSync` временного каталога: повторная попытка, затем игнорировать `EBUSY`. Production-генератор MUST NOT глотать `EBUSY`. Альтернатива: игнорировать `EBUSY` в `fileSystemHelpers.rmdir` — отвергнута; это не изменение production-генератора.

5. **Отказывать в mkdir/write корня диска в production.** Защита перед mkdir/write для `/`, `D:\`, `C:\` (и эквивалентных форм со слешем после нормализации). Тесты успешной записи MUST использовать настоящий временный каталог, не `'/'` как фиктивный каталог вывода. Отдельные тесты MUST ожидать понятную ошибку для `/` и `D:\`. Альтернатива: оставить замоканные записи в `'/'` — отвергнута; на Windows это корень диска.

6. **Пути Git CLI — POSIX.** `readSpecFromGit` MUST передавать `test/spec/v3.json` в `git show`, никогда `test\\spec\\v3.json`. Конвертировать разделители после того, как путь сделан относительным к репозиторию; не использовать нативный `path.normalize` как путь Git. Альтернатива: экранировать Windows-пути для Git — отвергнута; Git хочет POSIX-пути внутри репозитория.

7. **Сравнение снимков нормализует только `\n`.** `toMatchSnapshot` MUST нормализовать и expected, и received к `\n` перед сравнением. EOL файлов генератора не меняется. Альтернатива: переписывать сгенерированные файлы в LF — отвергнута; вне этого изменения.

8. **Без работы по Language / lookup.** НЕ редактировать `CONTEXT.md`. Без новых терминов глоссария. Строки дисковых путей — это не Tree `$ref` / `$ref` lookup.

## Risks / Trade-offs

- **[Риск] FS API на Windows по-прежнему получают `/`** → Node `fs` принимает `/`; хелперы уже отдают эту форму. Сохранить отказ писать в корень диска, чтобы `'/'` никогда не был целью записи.
- **[Риск] `EBUSY` игнорируется слишком широко** → Хелпер только тестовый, ограничен очисткой временного каталога; production `rmdir` не меняется.
- **[Риск] Хелпер снимков скрывает реальное расхождение содержимого** → Складываются только `\r\n` vs `\n`; остальные байты содержимого по-прежнему сравниваются.
- **[Компромисс] Тесты перестают использовать `path.join` для ожидаемых строк дисковых путей** → Чуть больше импортов хелпера; проверки совпадают с production-формой на любой ОС.
- **[Компромисс] Тесты успешной записи нуждаются в настоящем временном каталоге** → Чуть медленнее, чем замоканный `'/'`; избегаем записи в корень диска.
