# `$ref` lookup после SwaggerParser

Как получить схему по `$ref`, когда парсер уже открыл файлы. Имена терминов — в `CONTEXT.md` (Language). Почему не `path.resolve` — `docs/adr/0001-ref-lookup-uri-and-parser-keys.md`. Здесь — порядок действий.

Реализация: `src/core/utils/refLookup.ts`. Context.`get` / `exists` / обход Pointers только делегируют. Запись `.ts` и CLI — `pathHelpers`. `PathApi` нет. Если снова захочется «нормализовать путь» через `path.resolve` — вы решаете не ту задачу.

---

## Задача одной фразой

После `SwaggerParser.resolve()` файлы уже в словаре парсера. Нужно:

**Tree `$ref` + Parent source file → Canonical Ref (= ключ `$Refs`) → `refs.get` / `refs.exists`.**

Это не чтение диска и не «сделать путь одинаковым на Windows и Unix». Это найти **то имя**, под которым парсер уже хранит файл.

---

## Что сделал парсер, а что нет

Вызов: `parser.resolve(корневой файл)`. Не `dereference`, не `bundle`.

Уже сделано:

- Открыты корневой файл и внешние файлы, на которые он смог пройти по `$ref`.
- Содержимое лежит в `$Refs`. Список файлов: `refs.paths()` (обычно абсолютный путь со `/`).

Не сделано:

- Строки `$ref` в YAML **не переписаны**. Там по-прежнему `./Pet.yaml` и `#/components/schemas/Foo`.
- `refs.get(строка)` считает строку **от корня спеки**, не от файла, где вы сейчас стоите.

Поэтому `refs.get('Pet.yaml')` из `schemas/Owner.yaml` **не работает**: парсер ищет `Pet.yaml` рядом с корнем. Родителя знает только наш обход дерева.

`dereference()` развернул бы ссылки в объекты — тогда lookup не нужен. Генератору нужны живые `$ref`, чтобы понять, какой `.ts` импортировать.

---

## Три разных вещи

| Что | Зачем |
|-----|--------|
| Tree `$ref` | Как написано в YAML |
| Canonical Ref | Точное имя для `refs.get` (файл парсера + Pointer) |
| Virtual file map | Куда писать `.ts`, не откуда брать схему |

Карта файлов **не** заменяет lookup. В ней нет объектов схем.

---

## Алгоритм `$ref` lookup

Два шага подготовки, один шаг чтения. Третий «на всякий случай» не нужен.

### 1. Таблица имён в момент attach

Парсер уже открыл файлы. Строим таблицу:

- ключ — упрощённое имя **для сравнения**;
- значение — **точная** строка из `refs.paths()`.

Упрощение только чтобы найти то же имя, если слеши, `%20` или регистр буквы диска другие. Это не новый публичный формат.

Правила сравнения:

1. `%20` → пробел
2. `\` → `/`
3. схлопнуть лишние `/` (не трогаем редкие сетевые пути `\\server\share` — их пока нет в модели)
4. на Windows — один регистр хотя бы у буквы диска

В `refs.get` уходит **значение** из таблицы, не ключ сравнения.

Если файла нет в таблице — ссылки **нет**. Не подставлять «похожий» `Pet.yaml`. Не искать файл на диске. Сломанный путь в чужой спеке не чиним; об этом может сказать strict, не lookup.

### 2. Перевод (родитель, Tree `$ref`) → Canonical Ref

**Родитель** — абсолютный путь файла, где стоит `$ref`, **без** `#`.

- Если Tree `$ref` начинается с `#` и родителя не передали — родитель = Entry file (корневой файл спеки).
- Если Tree `$ref` — относительный файл (`Pet.yaml`, `./x.yaml`) и родителя нет — это ошибка контракта, не «подставь корень».
- Если вызывающий передал `файл#/Pointer` или `./relative.yaml` как родителя — это тоже ошибка контракта. Сначала отрезать `#` нельзя считать нормой API; править вызовы.

Дальше:

1. Отрезать Pointer: первое `#`. Слева файл, справа `#/…` (или пусто). Pointer **никогда** не отдавать в `path.join` / `path.normalize`.
2. Файл пустой (`#/components/schemas/Foo`) → Canonical Ref = имя родителя из таблицы + Pointer. Диск не трогаем.
3. Файл начинается с `http://` или `https://` → это Remote `$ref`. Canonical Ref = эта URL-строка (с Pointer как было). Path API не трогаем. В карту `.ts` не кладём.
4. Иначе это ссылка на файл (относительная, абсолютная, изредка `file://`):
   - Собрать базовый URL родителя **вручную**: `file:///C:/...` или `file:///home/...`. Не звать host `pathToFileURL` для строки `C:/...`, если процесс не Windows — получится мусор.
   - `new URL(файлСоСлешами/, база)` — как в браузере, одинаково на macOS и Windows.
   - Если получился не `file:` — как Remote `$ref`.
   - Если `file:` — взять путь, найти **точное** имя в таблице. Нет в таблице → ссылки нет.
   - Canonical Ref = точное имя + Pointer.

Это **не** `path.resolve`. `path` зависит от ОС процесса. `$ref` — URI.

### 3. Чтение

```
get(tree $ref, родитель)    = refs.get(Canonical Ref)
exists(tree $ref, родитель) = refs.exists(Canonical Ref)
```

Поведение строгое: нет в таблице / нет у парсера → `exists` = нет, `get` — как у парсера (ошибка). Не смягчать.

Тот же перевод (шаги 1–2) нужен, когда обходим дерево и собираем Pointers для карты файлов. Два разных «канона» в Context быть не должно.

Semantic diff — другой конвейер, эту инструкцию на него не распространяем.

---

## Что попадает в список Canonical Ref

Только то, на что **есть** Tree `$ref` при обходе уже открытых файлов.

- `$ref: ./Pet.yaml` без `#` → Canonical Ref на **весь файл**.
- `$ref: #/components/schemas/Foo` → файл + Pointer.
- Схема лежит в файле, но на неё никто не сослался → **не** Canonical Ref.
- Файл просто открыт парсером, входящего `$ref` нет → **не** Canonical Ref.

Этот список кормит модели / reuse / strict. Он не равен «все ключи `components.schemas`».

---

## Output mapping (не lookup)

Canonical Ref → запись в Virtual file map → путь `.ts`.

Схему отсюда не брать. Remote `$ref` в карту не класть.

---

## Примеры

Родитель везде уже абсолютный, как в `refs.paths()`.

| Tree `$ref` | Родитель | Canonical Ref для `refs.get` |
|-------------|----------|------------------------------|
| `#/components/schemas/Foo` | `/home/dev/api.yaml` | `/home/dev/api.yaml#/components/schemas/Foo` |
| `./schemas/Pet.yaml` | `/home/dev/api.yaml` | `/home/dev/schemas/Pet.yaml` |
| `Pet.yaml` | `/home/dev/schemas/Owner.yaml` | `/home/dev/schemas/Pet.yaml` |
| `../common.yaml#/defs/X` | `/home/dev/schemas/Owner.yaml` | `/home/dev/common.yaml#/defs/X` |
| `https://ex.com/a.json#/Foo` | любой | `https://ex.com/a.json#/Foo` (без `.ts`) |

Windows в каноне парсера обычно `C:/...`, не `C:\...`. Таблица подставит точную строку, если парсер написал иначе.

`new URL('Pet.yaml', 'file:///C:/proj/schemas/Owner.yaml')` → `file:///C:/proj/schemas/Pet.yaml`. Так и должно быть на darwin.

## Что не делать

1. Не кормить `path.normalize` / `join` / `resolve` строкой `файл#/Pointer`.
2. Не вызывать `refs.get(сырой Tree $ref)` без родителя, если это не чистый Pointer.
3. Не строить «наш красивый POSIX» и надеяться, что он равен ключу парсера. Сначала таблица.
4. Не класть схемы в Virtual file map. Не делать `exists` по списку увиденных Pointers.
5. Не звать host `pathToFileURL` для `C:/...` на не-Windows.
6. Не чинить кросс-ОС новым helper рядом с `pathHelpers`. Для `$ref` — URI + таблица. `pathHelpers` — CLI и запись `.ts` на диск.
7. Не считать `resolve()` равным `dereference()`.
8. Не угадывать другой файл по имени (`Pet.yaml` «какой-нибудь»). Не искать на диске.
9. Не закладывать сейчас `\\server\share` — нет живого требования.

---

## Реализация

Один хозяин перевода для Context: `RefLookup.toCanonicalRef`. Context.`get` / `exists` только делегируют. Сбор Pointers для карты — тот же перевод. Склейка файла — `joinTreeRefFile`; её же вызывает semantic expand. Expand не импортирует класс `RefLookup` и не бросает `RefLookupError`: неразрешённый `$ref` остаётся объектом.

Не тащить сюда плагины и расчёт output-пути (это Output mapping в Context).

Проверки, без которых снова разъедется:

- `#/Foo` + родитель → `родитель#/Foo`, Pointer со `/`, не `#\Foo`
- `Pet.yaml` из `.../schemas/Owner.yaml` → соседний файл
- строки `C:/...` на darwin через `new URL`, без `path.win32` как костыля для склейки
- в YAML `C:\proj\api.yaml#/Foo`, в `paths()` лежит `C:/proj/api.yaml` → `get` попадает
- `path.*` никогда не видит строку с `#`
- нет родителя + `./Pet.yaml` → ошибка контракта, не тихий fallback на корень
- нет родителя + `#/Foo` → Entry file + Pointer
- файла нет в таблице → `exists` = нет, без второго `Pet.yaml`
